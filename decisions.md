# Decision Log

- **D1 (major)** Coverage gaps closed via typed wrappers, not raw dialog alone — 24 new wrappers in `src/service.ts` + UI exposure in `src/components/actions.tsx`. Why: user chose "audit + close gaps"; rare ops (SEP/backplane, serialnumber targeting, `encode`, i2caddress UI) stay on the raw-command escape hatch per existing service.ts comment. Ref: docs/hpssa-coverage.md.
- **D2 (major)** Full PF6 redesign keeps hand-built table markup instead of `@patternfly/react-table` — package absent from node_modules/deps. Fixed tables to valid PF6 structure + a11y instead of adding a dependency for what markup can do. Ref: src/app.tsx.
- **D3 (minor)** Removed self-rendered PageSidebar/title chrome; plugin runs inside Cockpit shell frame, uses horizontal-subnav Nav like current Cockpit apps. Ref: src/app.tsx.
- **D4 (minor)** Parser fixes driven by live-host output: enclosure status now captures to end-of-line (`Not OK: …` was truncated to `Not`), controller mode regex `\w+` → `[^)]+` (two-word modes like `HBA Mode`). Ref: src/ssacli.ts, test/parser-check.mjs.
- **D5 (minor)** Review fixes: app.scss dead `--pf-v6-global--*` vars repointed to `--pf-t--global--*` tokens (PF6 ships no pf-v6-global aliases); `showSsdInfo` emits documented `<target> show ssdinfo` (verified invalid without `show` on live host); `ldSetLabel` passes raw label (cockpit.spawn is argv-based, literal quotes reached ssacli); `statusColor/statusIcon` treat `Not OK:*`/`*critical*` as red; dropped `role="button"` on clickable rows.
- **D6 (minor)** SEP/backplane/serial/ssdphysicaldrive/encode wrappers added per todo; enclosure-by-serial requires a controller qualifier (verified against live CLI — bare `enclosure serialnumber=` errors with "Expecting controller in target"). Ref: src/service.ts, src/components/actions.tsx.
- **D6b (minor)** Package CI added as .github/workflows/build-packages.yml (RPM via cockpit tasks container + `make rpm`; DEB via ubuntu + dpkg-buildpackage over a freshly built dist/). Why: /dist/ is gitignored, so the DEB job builds the bundle first (fixed after review of generated workflow); artifacts uploaded per-run and attached to tag releases.
- **D7 (minor)** SEP/backplane/serial/ch/ssdphysicaldrive/encode implemented as typed wrappers + UI where meaningful (SEP/backplane/SSD shows, SEP firmware form, LD encode dialog); ops without a natural UI surface stay on the raw-command escape hatch per D1. Ref: src/service.ts, docs/hpssa-coverage.md.
- **D8 (major)** build-packages.yml reworked after replaying its exact steps in containers (ghcr.io/cockpit-project/tasks = Fedora 44, ubuntu:24.04) — it had never run. One `release` job attaches both .deb/.rpm after rpm+deb succeed (two jobs calling action-gh-release can race to create the release); deb gets the tag version via `sed` on debian/changelog from `make print-version`; checkout@v7 + `fetch-depth: 0` in both jobs; dropped the `dnf install` step (tasks image ships rpmbuild/gettext/node/jq/file/appstream-util, and the mirror call was flaky). Ref: .github/workflows/build-packages.yml.
- **D9 (major)** `@patternfly/patternfly` 6.5.0 → 6.6.1: 6.5.0 is the only release that moved files under `dist/`, so cockpit's pinned `pkg/lib` `@forward "@patternfly/patternfly/sass-utilities"` fails on a fresh install (local dev only worked from a stale 6.1.0 node_modules). 6.4.0/6.6.1/6.7.0 keep the root layout. Ref: package.json.
- **D10 (minor)** `eslint-plugin-promise` 7.3.0 → 6.6.0 (peer of eslint-config-standard 17 is ^6): package-lock.json is gitignored, so CI's fresh `npm install` ERESOLVEs and both package jobs died before building. Ref: package.json.
- **D11 (minor)** spec `rebuild_bundle` is now opt-in (`rpmbuild --define "rebuild_bundle 1"`) instead of auto for Fedora ≥42: `make rpm` invokes rpmbuild directly, which never installs BuildRequires, so the rebuild would fail (image has nodejs-esbuild but no distro react/patternfly modules). Ref: packaging/cockpit-hpssa.spec.in.
- **D12 (minor)** Build/install blockers fixed: `Makefile` VERSION uses `git describe --tags` and strips a leading `v` (tag `v1.2.3` → package `1.2.3`), rpm cleanup is `rm -rf` (rpm ≥4.20 ignores `_buildrootdir`, so `build/` never exists); `debian/control` gained a `Maintainer` (dpkg-genchanges hard-fails without it); `OWNER` placeholders → `volfco` in changelog/spec/metainfo/PKGBUILD. Verified: `dnf install` on Fedora 44 and `apt-get install` on Ubuntu 24.04 both succeed. First real Actions run added: dpkg's Debian vendor injects a builtin `build-essential:native` build-dep that the runner image no longer ships (bare-container repro masked this) → installed explicitly; artifact actions bumped upload v4→v7 / download v4→v8 / gh-release v2→v3 (node24, same inputs). Ref: Makefile, debian/control.
- **D13 (minor)** Independent review of the CI change returned no blockers; applied its nits — metainfo `update_contact`/`developer` were starter-kit leftovers → volfco (re-validated with appstream-util), unchecked items moved out of todo's Done section, duplicate D6 renumbered D6b; deferred spec `Source0/1` URL and PKGBUILD arch/license findings to todo.md. Ref: todo.md.
- **D14 (major)** PF6 layout repair explicitly imports Cockpit's page foundation plus the Table, table-grid, and used utility styles; `Page sidebar={null}` prevents a second sidebar gutter inside Cockpit. Hardware galleries use responsive 30rem minimum columns and single-column card property lists. Responsive table cells carry labels; expanded drive details span the full row. Ref: src/app.tsx, src/app.scss; [PatternFly tables](https://www.patternfly.org/components/table/html/).
- **D15 (minor)** Controller cards use the PF6 actionable-only API; settings separate descriptions and current values, dialog IDs are scoped, and action menus portal to the body with a bounded scrolling height. Isolated Firefox BiDi checks use typed hardware fixtures and mock every storage call. Ref: src/components, test/ui-check.mjs, test/ui/fixtures.ts; [PatternFly actionable cards](https://www.patternfly.org/components/card/react/actionable/).
- **D16 (minor)** Command outcomes are now always presented: dialog-triggered data refreshes run in the background (`loadData(true)`) so open modals stay mounted and their success/error result remains readable (a foreground reload unmounted the settings modal before its success alert could be seen — reproduced in browser before the fix); Rescan/Rescan all open the existing OutputDialog one-click (user choice) with a new success banner, instead of silently discarding the promise; Escape/backdrop dismissal is ignored while a command runs in every command dialog (Form/Confirm/Raw/Output; Output's Close is disabled while running). Background refresh failures keep stale data rather than unmount dialogs; foreground loads keep the Retry alert. Ref: src/app.tsx, src/components/dialogs.tsx; regression coverage in test/ui-check.mjs (delayed mock discovery + delayed modify spawn observe the in-flight modal, Escape-ignored, settings result, rescan results).
